# 2. Latar Belakang

Project ini bertujuan membangun aplikasi kas sederhana yang dapat digunakan oleh beberapa user untuk mencatat, memonitor, dan mengelola transaksi keuangan.

Aplikasi harus memiliki struktur kode yang rapi dan mudah dikembangkan. Arsitektur project sejak awal harus mempertimbangkan pemisahan antara:

- Authentication
- Module aplikasi internal
- Public/frontend
- Business logic
- Database layer
- Authorization
- UI/layout

Project tidak ditujukan sebagai sistem akuntansi penuh, tetapi sebagai sistem pencatatan kas yang sederhana, terstruktur, dan dapat dikembangkan menjadi sistem keuangan yang lebih kompleks.

---

# 3. Tujuan

## 3.1 Tujuan Utama

Membangun aplikasi kas multi-user yang memungkinkan user untuk:

1. Login ke sistem.
2. Mengelola data transaksi kas.
3. Melihat saldo kas.
4. Melihat pemasukan dan pengeluaran.
5. Melihat histori transaksi.
6. Melihat laporan kas.
7. Mengelola kategori transaksi.
8. Mengelola user sesuai hak akses.
9. Mengetahui aktivitas/transaksi yang dibuat oleh user tertentu.

## 3.2 Tujuan Teknis

Project harus:

- Menggunakan Laravel 12.
- Menggunakan Blade sebagai templating engine.
- Menggunakan Tailwind CSS.
- Menggunakan TailAdmin sebagai UI theme.
- Menggunakan MySQL.
- Mengikuti prinsip clean code.
- Menghindari controller yang terlalu besar.
- Memisahkan business logic dari controller.
- Menggunakan Form Request untuk validasi.
- Menggunakan Policy/Gate untuk authorization.
- Menggunakan Service untuk business logic yang kompleks.
- Menggunakan Eloquent secara terstruktur.
- Menggunakan database transaction pada operasi yang membutuhkan atomicity.
- Memiliki struktur folder yang konsisten.
- Mudah dikembangkan menjadi aplikasi yang lebih besar.

# 18. Controller Convention

Controller hanya bertanggung jawab terhadap HTTP layer.

Controller **tidak boleh** menjadi tempat business logic yang kompleks.

Contoh yang dihindari:

```php
public function store(Request $request)
{
    // 100+ lines business logic
}
```

Gunakan:

```php
public function store(StoreTransactionRequest $request)
{
    $this->transactionService->create(
        $request->validated(),
        $request->user()
    );

    return redirect()
        ->route('modules.cash.transactions.index')
        ->with('success', 'Transaction created successfully.');
}
```

Business logic berada di Service.

# 22. Authorization

Authorization harus dilakukan melalui:

- Policy.
- Gate.
- Middleware role/permission jika diperlukan.

Contoh:

```php
$this->authorize('update', $transaction);
```

Jangan menyebarkan kondisi seperti:

```php
if (auth()->user()->role === 'admin')
```

di banyak controller/view.

Role checking harus memiliki abstraction yang jelas.

# 23. Enum

Untuk value yang sifatnya fixed gunakan Enum PHP.

Contoh:

```php
enum TransactionType: string
{
    case INCOME = 'income';
    case EXPENSE = 'expense';
}
```

Enum lain:

```text
UserRole
UserStatus
CategoryType
TransactionType
```

Tujuannya menghindari magic string:

```php
if ($transaction->type === 'income')
```

Jika memungkinkan gunakan:

```php
if ($transaction->type === TransactionType::INCOME)
```

```text

max:255
```

## Kesimpulan

MVP Sistem Kas ini menggunakan pendekatan **modular Laravel monolith** dengan Blade + Tailwind CSS + TailAdmin + MySQL.

Fokus utama arsitektur adalah:

```text
Clean Code
+
Separation of Concerns
+
Thin Controller
+
Service Layer
+
Policy Authorization
+
Form Request Validation
+
Reusable Blade Components
+
Consistent Folder Convention
```

Struktur `auth`, `modules`, dan `frontend` dibuat konsisten dari sisi **Controller, Request, Service, View, dan Route**, sehingga ketika aplikasi bertambah besar, developer tetap dapat menemukan seluruh kode berdasarkan domain/module dengan mudah.

TailAdmin diposisikan sebagai **UI/design layer**, bukan sebagai struktur arsitektur aplikasi. Dengan demikian, UI dapat dikembangkan atau bahkan diganti tanpa mengganggu business logic dan database layer.
